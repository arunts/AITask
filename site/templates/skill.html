ai-task-author

A skill that teaches Claude Code, Codex and other coding agents to turn “I want a task that…” into an AITaskDefinition file. It interviews you briefly, writes the prompts, picks built-in or MCP tools, validates the file, and tells you how to import it.

Install

The skill is a folder with a SKILL.md at its root, the layout the Agent Skills format defines and that Claude Code, Codex and a growing list of agents load. Unzip it where your agent looks for skills, start a new session, and the agent picks it up whenever a task for AITaskRunner comes up.

Claude Code

Personal skills live in ~/.claude/skills/; project skills in .claude/skills/ inside the repository.

mkdir -p ~/.claude/skills
unzip ~/Downloads/ai-task-author.zip -d ~/.claude/skills/

Codex

Personal skills live in ~/.codex/skills/; project skills in .codex/skills/. Recent versions also read .agents/skills/. Type /skills to confirm it loaded.

mkdir -p ~/.codex/skills
unzip ~/Downloads/ai-task-author.zip -d ~/.codex/skills/

Any other agent

If it reads the Agent Skills format (Cursor, Gemini CLI and others do), point it at the folder. Otherwise paste the contents of SKILL.md into your instructions file, such as AGENTS.md, and tell the agent the references folder is beside it.

unzip ai-task-author.zip -d ./skills/
# then in AGENTS.md: "For AITaskRunner tasks, follow skills/ai-task-author/SKILL.md"

From a checkout of the repository, a symlink keeps it current: ln -s "…/AITaskRunner/skills/ai-task-author" ~/.claude/skills/ai-task-author. The scripts need only Python 3; nothing else is installed.

Try it

Say what the task should do each time it runs. The skill asks only the questions that change the file, and suggests a default for each so “looks good” is a complete answer.

  • “Make me an AITaskRunner task that summarises the PDFs in a folder each week.”
  • “I want a task that reads my staged git diff and drafts a commit message. Never let it commit.”
  • “Write a task for AITaskRunner that fetches a URL and gives me three bullets. It can use an MCP server if it has to.”
  • “Turn this prompt I keep pasting into a task with variables for the topic and the tone.”

You get a <Task Name>.json and the validator's output.

How it works

  1. Understand the task. Restate in one sentence what the task produces, then work out what changes per run (variables), what the model has to touch (tools), and whether it needs to check in mid-run (interactive).
  2. Ask only what changes the file. Inputs and their defaults, which folders it may read or write, the output shape, whether it may ask questions, and which MCP server if one is needed. All in one message.
  3. Write the prompts. System prompt as the standing rules with Always / Never / Only rules; user prompt as numbered steps with the exact commands and tool names. Short, because small local models and Apple's 4K window reward it.
  4. Pick tools. The built-in shell first. An MCP server only when the shell cannot do it well, following a ladder that ends with “say no and offer a shell fallback” rather than inventing a server. Never a secret in the file.
  5. Write, validate, deliver. Pretty-printed JSON, the validator run until it exits 0, a short summary, and the import steps.

What is inside

  • ├── SKILL.md — the workflow the agent follows
  • ├── README.md — install notes and layout
  • ├── references/
  • │ ├── task-format.md — every field of the file format
  • │ ├── builtin-tools.md — the Shell tool, file recipes, ask_user
  • │ └── mcp-servers.md — when and how to add an MCP server; known servers
  • ├── scripts/
  • │ ├── validate_task.py — checks a file the way the importer does
  • │ └── list_builtin_tools.py — prints the live built-in tool list from the app's sources
  • └── assets/examples/ — four complete task files, also in the repository

The validator

A standard-library Python script that mirrors the app's importer: the same errors that make the app refuse a file, plus warnings for things that import fine but go wrong at run time, such as a placeholder with no variable or a prompt that names a tool that is not attached. It prints a preview of the task as the app would show it.

python3 ~/.claude/skills/ai-task-author/scripts/validate_task.py "Summarise Notes.json"
✓ Summarise Notes.json: importable (version 1)
  Name:       Summarise Notes Folder
  Traits:     Tools · 2 variables
  Variables:
    {{notes_folder}} (folder, default "~/Notes") — Folder whose .md and .txt files are summarised
    {{max_files}} (text, default "10") — Stop after this many files
  Tools:
    Shell (shell__…): all tools (run)

Exit code 0 means the app will import it; 1 lists the errors; warnings never block. Use - to read from stdin.
